# Golden trajectory

## Ordered path

1. Reproduce: write Year, Month, java.sql.Date and Locale with new KubernetesSerialization() and compare with the 2.x forms the issue lists; generate a CRD for a spec with byte[], char[], QName, int and long fields and look at the schema.
2. Add Jackson2JdkTypesModule to kubernetes-model-common next to GoCompatibilityModule: a Year serializer that follows WRITE_DATES_AS_TIMESTAMPS and reports a plain string, a java.sql.Date serializer writing toString() and reporting format date and a deserializer reading yyyy-MM-dd as a local date, Locale written with toString() and read (values and keys) from the _# form, BCP 47 and the legacy forms, and Month serialized as a plain enum through a Serializers hook.
3. Register it in the no-argument KubernetesSerialization constructor, in Serialization.yamlMapper() and in ResolvingContext's default mapper, but not in configureMapper.
4. In AbstractJsonSchema, replace Jackson's reported schema for byte[]/ByteBuffer (base64 string, format byte), char[] and QName (also a ReferenceSchema) with strings unless the property has its own serializer or converter, add int32/int64 formats from the Java type, map @Size on binary values to base64 lengths, and let java.sql.Date keep format date; in AbstractCustomResourceHandler stop turning date properties into date printer columns.
5. Regenerate the approved CRDs and run the model common, client API and CRD generator tests offline.

## Deliverables and red lines

- `D1` at `main sources (src/main/java) of the modules of the graded build under /app`: A public Jackson 3 module io.fabric8.kubernetes.model.jackson.Jackson2JdkTypesModule in kubernetes-model-common writes Year, Month, java.sql.Date and Locale (values and map keys) exactly as Jackson 2.x did, honouring @JsonFormat and WRITE_DATES_AS_TIMESTAMPS, reads both the 2.x and the Jackson 3 / BCP 47 forms back into the same value (java.sql.Date yyyy-MM-dd as a local date in any timezone), reads anything else as Jackson 3 does, and reports the schema it writes.
- `D2` at `main sources (src/main/java) of the modules of the graded build under /app`: new KubernetesSerialization() (so Serialization.jsonMapper() and the default client), Serialization.yamlMapper() and the CRD generator's default mapper write these four types byte-identical to 7.9.0 and read both forms; a mapper the caller passes to KubernetesSerialization keeps its own handling of them.
- `D3` at `main sources (src/main/java) of the modules of the graded build under /app`: The CRD generator maps types like controller-gen and never emits a schema that rejects what the client writes: byte[]/ByteBuffer (also in Optional, lists, map values) string/byte with @Size bounding the base64 length, Byte[]/List<Byte> integer arrays, char[]/QName string, int32/int64 formats for int/long values only, Year/Month/Locale string, java.sql.Date string/date, a property with its own serializer keeping the schema it reports, and @PrinterColumn on a date property a string column.
- `RL1`: The graded result is computed from the agent's regular files under src/main/java of the 13 modules of the graded build that have one; tests, test resources, every pom.xml and every other file are taken from the pristine base with the hidden tests, and symlinks are dropped. Enforced by tests/grading/grade.sh, which replaces those trees in a copy of /opt/base-src with the agent's and builds every module of the graded build from it.
- `RL2`: No network is reachable from the agent environment, so the merged fix cannot be fetched; Maven runs offline against the prefetched repository. Enforced by task.toml [environment] and [agent] network_mode no-network, and the offline settings.xml and repository in the environment image.
- `RL3`: Everything that works at the base keeps working: every test of the model common, client API, CRD generator API and CRD generator approval test modules that passes at the base with the hidden tests applied passes by name and count, and a mapper a caller passes to KubernetesSerialization keeps its own handling of the JDK types. Enforced by the frame item R7, which the gate requires, and the authored guard R6.
- `RL4`: Every stage that compiles or runs agent code runs as uid 20003 with a cleared environment and a fresh home; the graded tree and the Maven repository are root-owned outside the build stage, each test stage can write only its own module, and root copies its reports before the next stage; Reward Kit runs as uid 20002 only after every uid 20003 process is gone.
